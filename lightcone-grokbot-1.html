🔧 1. 科技背景（13）
Lightcone · YC
Lightcone 是 Y Combinator（简称 YC）的播客。本集从 AI 写代码谈到销售、营销和客服怎么用 bot，也提到 YC 自己搭的 bot 聊天系统。
Garry Tan · Jared Friedman
本集两位主持人。Garry 从自己的 OpenClaw 使用经历谈到给 bot 分工，也聊到自己的 GStack。Jared 用 YC 的 Quartermaster 举例，并请 Lauren 拆解从 Slack 需求到 PR 的流程。
Roman Ugarte · Lauren Tan（@poteto）
两人是 SpaceXSI 的 Grok Bot 核心团队成员。Roman 主要讲产品设计和团队使用案例，Lauren 用自己的工程工作流演示。原型约七周搭成的时间来自 Roman 自述，开场也提到从第一行代码到上线用了七周。
Grok Bot · AI 队友
Roman 把 Grok Bot 描述为创建 AI 队友的产品。用户可以为 bot 配置名字、身份、职责、技能和工具，让它持续运行并主动跟进工作。
outer loop · last mile
Lauren 用 outer loop 指围绕写代码展开的工作，例如在 Slack 收集需求、与同事讨论并把背景传给智能体。她也把衔接背景信息与实际执行的这一步叫作 last mile（最后一公里）。
connector · MCP
连接器让 bot 接入 Slack 等工作工具，能在讨论现场取得上下文。MCP（Model Context Protocol）是让 AI 应用连接外部数据和工具的协议。Roman 提起 MCP 时强调，bot 要能用上实际工作所需的工具。
Team Bots · 团队共享
共享 bot 可以集中吸收团队成员贡献的做法。Lauren 用销售举例：大家一起维护共享的专家 bot，把报价、交易等流程里可复用的经验沉淀进去。
身份、凭证与授权
身份验证用于确认当前是谁，授权用于决定能做什么，凭证用于证明身份或取得访问权。Roman 用新员工入职类比按角色限定权限。Jared 举的 Quartermaster 则会在相应协作场景中继承用户权限。
只读起步 · Data Bot
Roman 举例说，团队给 Data Bot 数据库只读权限，让它在 Slack 回答分析问题。体验稳定后，可以逐步委派需要执行操作的任务，再考虑交给 bot 持续负责的目标。
bot 之间的协作
Lauren 会让自己的工程 bot Potato 找 Data Bot 查询受影响的用户数量。她能在 Slack 讨论串里看到两者的交流，Grok Bot 应用里也有 bot 聊天记录。
PR · 代码审查
PR 是 pull request，即请求把一组代码改动合并进目标分支。团队可以在合并前审查改动、运行自动检查。对话中从每月 2000 多个 PR 增至 4000 多个的数字由 Jared 提出、Lauren 在节目中确认，属于访谈中的团队自述。
Cursor · 云端智能体
Lauren 以前常用 Cursor 处理工程工作。演示中 Potato 启动了 Cursor 云端智能体，它在独立虚拟机里运行应用、做原型，并把视频和截图带回 Slack 讨论。
pstack · GStack
pstack 是 Potato Stack，Lauren 受 Garry 的 GStack 启发整理的一套工程技能。按 Lauren 自述，内部版本装在团队的代码仓库里，云端智能体也能调用这些技能。她还把技能开源到了 Cursor 插件仓库。
